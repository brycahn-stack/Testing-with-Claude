# Sift — Setup

Everything that has to happen outside the code before Sift runs on a device.
You shouldn't need to read any Swift to get through this.

There are three independent pieces. **Signing** is required. **Google** and
**Obsidian** are optional — the app builds and runs without either, it just has
fewer places to file things.

---

## 0. Prerequisites

- **Xcode 15+** (iOS 17 / watchOS 10 deployment targets)
- **XcodeGen 2.38+** — `brew install xcodegen`
- **A paid Apple Developer account.** Required for HealthKit: the entitlement
  can't be signed on a free personal team.
- A **real iPhone + paired Apple Watch.** The simulator can't do
  WatchConnectivity file transfer, microphone capture, or HealthKit data
  end-to-end.

```bash
cd Sift
xcodegen generate
open Sift.xcodeproj
```

> `Sift.xcodeproj` is generated, not committed. Re-run `xcodegen generate`
> after any change to `project.yml`. Don't edit project settings in Xcode's UI —
> they'll be overwritten on the next generate. Edit `project.yml` instead.

## 1. Signing — required

### Set the team ID

In `project.yml`, line ~27:

```yaml
settings:
  base:
    DEVELOPMENT_TEAM: ""        # ← put the 10-character Team ID here
```

The Team ID is in [developer.apple.com](https://developer.apple.com/account) →
Membership Details. It looks like `A1B2C3D4E5`.

Then `xcodegen generate` again.

### Bundle identifiers

Three targets, three IDs:

| Target | Bundle ID |
|---|---|
| Sift (iOS) | `com.brycahn.sift` |
| SiftWatch (watchOS) | `com.brycahn.sift.watchkitapp` |
| SiftCore (framework) | `com.brycahn.sift.Core` |

**If the developer account isn't under the `brycahn` domain**, change
`bundleIdPrefix` at the top of `project.yml` and the three
`PRODUCT_BUNDLE_IDENTIFIER` lines to match your reverse-domain, then regenerate.
Anything consistent works — but note that **changing the iOS bundle ID means the
Google OAuth client has to be created against the new one** (section 2).

The watch app's `WKCompanionAppBundleIdentifier` must keep matching the iOS
app's ID, or the watch app won't pair. It's set in `project.yml` under the
`SiftWatch` target.

Signing is `Automatic`, so Xcode will register the App IDs and create profiles
on first build.

## 2. HealthKit — required capability, no configuration

Nothing to configure, but worth knowing what it asks for:

- The entitlement is **generated by XcodeGen** at
  `iOSApp/Support/Sift.entitlements`. Don't create it by hand.
- Automatic signing enables the HealthKit capability on the App ID for you.

**Sift requests read access and an empty share set.** It never writes to Apple
Health. That's deliberate: the watch already records the workout, so writing one
from a voice memo would create a duplicate *and* credit invented calories to the
user's Activity rings. Sift reads the watch's numbers and stores the sets and
reps itself, which HealthKit has no data type for.

If a reviewer or teammate asks why the app requests HealthKit at all: it reads
`HKWorkout`, heart rate, and active energy so a logged training session can show
the effort the watch measured next to the barbell numbers the watch can't see.

## 3. Google — optional (Gmail + Google Calendar)

Until this is done, the **Connect** buttons in the Connections tab are disabled
and the app shows a banner saying so. Everything else works; scheduling memos
fall back to Apple Calendar and email intents fall back to Reminders.

### Create the OAuth client

1. [console.cloud.google.com](https://console.cloud.google.com) → create a
   project (e.g. "Sift").
2. **APIs & Services → Library** → enable **Gmail API** and
   **Google Calendar API**.
3. **APIs & Services → OAuth consent screen** → **External** → add the intended
   users as **test users**.
4. **Credentials → Create Credentials → OAuth client ID → iOS** → bundle ID
   `com.brycahn.sift` (or whatever it was changed to in section 1) → copy the
   client ID.

### Paste it in

`iOSApp/Google/GoogleService.swift`, near the top:

```swift
static let clientID = "YOUR_CLIENT_ID.apps.googleusercontent.com"
```

That's the only edit. iOS OAuth clients have no secret — the flow uses PKCE
(`ASWebAuthenticationSession`), and the redirect URI is derived from the client
ID automatically. Tokens are stored in the iOS Keychain.

### Scopes, and what they permit

| Service | Scope | What it allows |
|---|---|---|
| Gmail | `gmail.compose` | Send mail and save drafts. **No inbox read access.** |
| Calendar | `calendar.events` | Create and edit events. Not other calendars. |

Both are "sensitive" in Google's tiering: usable with up to **100 test users
with no review**. Shipping publicly needs standard OAuth verification (~10 days)
but *not* the heavier CASA security assessment.

### Brand assets

The Gmail and Calendar tiles in the Connections list are **styled placeholders**,
not the real logos. Before any public release, download the official marks from
Google's brand resource pages (usage guidelines apply) and drop them into
`Assets.xcassets`. Same applies to the Obsidian gem, which is drawn as vector
paths in `iOSApp/Views/ObsidianMark.swift`.

## 4. Obsidian — optional, no setup

Nothing to configure and no account. In the Connections tab, tap **Choose Vault**
and pick the vault folder in Files. iOS returns a security-scoped bookmark, and
that bookmark is the whole connection.

Works with any vault iOS can reach — iCloud Drive, On My iPhone, or another
storage provider. If the vault syncs through iCloud Drive, notes written on the
phone appear on the Mac at the next sync.

## 5. First run

1. Select the **Sift** scheme, choose the paired iPhone, build.
2. Grant permissions when prompted: **Microphone**, **Speech Recognition**,
   **Reminders**, **Calendar**, **Health**.
3. On the watch, tap the mic and say something with an obvious shape —
   "remind me to call the dentist" or "squats, 5×5 at 225" — and watch it land
   in the Journal and Review tabs.

Run the unit tests with **⌘U**, or:

```bash
xcodebuild test -scheme Sift -destination 'platform=iOS Simulator,name=iPhone 15'
```

The tests cover categorization, routing, the Obsidian Markdown and append logic,
and the set/rep extractor. None of them need signing, a device, or any of the
connections above.

## Known state

The project has **never been compiled on an Apple toolchain** — it was written
in a Linux environment with no Swift compiler. The first build will surface
real errors. That's expected, and it's the most valuable next step: nothing
below the syntax level has been verified by a compiler.
